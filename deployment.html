AWS Cloud Services, Serverless Infrastructure & CI/CD Pipelines

PART 1: CLOUD & AWS FOUNDATIONS
1. Introduction to Cloud Computing
Meaning: Cloud Computing means storing, running, and managing applications on remote server infrastructure over the internet rather than on local physical computers.
Definition: The on-demand availability of computer system resources (computing power, storage, databases, networking) delivered over the internet with pay-as-you-go pricing.
Purpose: Eliminates expensive upfront hardware costs, enables global scaling within seconds, and ensures high availability and disaster recovery.
Example: Streaming movies on Netflix via cloud servers instead of buying physical DVD discs to store at home.
# Verifying Cloud CLI Connectivity (AWS CLI) aws sts get-caller-identity

2. Introduction to Amazon Web Services (AWS)
Meaning: AWS is the world's most comprehensive and broadly adopted cloud platform, offering over 200 fully featured services from global data centers.
Definition: A subsidiary of Amazon providing on-demand cloud computing platforms and APIs to individuals, companies, and governments on a metered pay-as-you-go basis.
Purpose: Powers production backends, databases, storage, security, machine learning models, and content delivery networks globally.
Example: Renting specialized industrial tools from a global equipment hub only when needed, rather than building your own factory.

PART 2: VIRTUAL SERVERS (AMAZON EC2)
3. Amazon EC2 (Elastic Compute Cloud) Overview
Meaning: EC2 provides scalable virtual servers in the cloud that you can configure and run 24/7 to host applications.
Definition: A web service that provides secure, resizable compute capacity in the cloud as Virtual Machines (Instances) running Linux or Windows operating systems.
Purpose: Gives complete root administrative control over virtual cloud servers to install web servers (Nginx, Apache), run Node.js/Python backends, and host databases.
Example: Renting a personal computer in a remote data center that stays turned on 24/7 with a dedicated public IP address.
# Connecting to a remote EC2 Linux Instance via SSH key pair ssh -i "my-key-pair.pem" ubuntu@ec2-54-210-100-20.compute-1.amazonaws.com

4. Provisioning & Configuring an EC2 Instance
Meaning: Launching a virtual server instance, setting firewall rules (Security Groups), and installing web server runtime environments.
Definition: Selecting an AMI (Amazon Machine Image OS), instance type, key pair, and configuring Security Groups (firewall rules for Port 80 HTTP, Port 443 HTTPS, Port 22 SSH).
Purpose: Prepares a live, secure cloud server environment ready to receive real user web traffic.
Example: Setting up a physical store, locking doors with custom security keys, and opening specific service windows for customers.

PART 3: OBJECT STORAGE (AMAZON S3)
5. Amazon S3 (Simple Storage Service) Overview
Meaning: Amazon S3 is an object storage service built to store and retrieve any amount of data from anywhere on the web safely.
Definition: An ultra-durable storage system storing data as Objects inside named containers called Buckets, offering 99.999999999% (11 9s) of data durability.
Purpose: Hosts static web assets (images, CSS, JS bundles), static websites, database backups, and media upload files reliably.
Example: A digital storage warehouse with infinite space where every single uploaded file gets a unique permanent web URL link.
# AWS CLI S3 Commands # Create a new bucket aws s3 mb s3://my-unique-app-bucket-2026 # Upload file to bucket aws s3 cp image.jpg s3://my-unique-app-bucket-2026/image.jpg # List files in bucket aws s3 ls s3://my-unique-app-bucket-2026
Task: Create a globally unique S3 bucket name in the AWS Console, upload an `index.html` file, and view its properties.
6. S3 Bucket Policies, CORS & Static Website Hosting
Meaning: Security configurations controlling access permissions, cross-origin web requests, and static website hosting features on an S3 bucket.
Definition: JSON Policy documents managing read/write permissions, CORS (Cross-Origin Resource Sharing) rules allowing browser access, and enabling static website hosting modes.
Purpose: Allows serving public images or hosting full static web apps (React, HTML5) directly from S3 without needing an EC2 server.
Example: Setting up a public bulletin board where anyone can read announcements, but only staff members can post new pages.
// JSON S3 Public Read Bucket Policy Example { "Version": "2012-10-17", "Statement": [ { "Sid": "PublicReadGetObject", "Effect": "Allow", "Principal": "*", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::my-unique-app-bucket-2026/*" } ] }
Task: Enable "Static Website Hosting" on an S3 bucket, attach a public-read bucket policy, and access the live website URL.
PART 4: SERVERLESS COMPUTING (AWS LAMBDA)
7. AWS Lambda (Serverless Computing) Overview
Meaning: A serverless event-driven compute service that lets you run backend code without provisioning or managing virtual servers.
Definition: Code executes automatically in response to triggers (HTTP requests, database updates, S3 file uploads) and scales automatically, charging only for exact compute time consumed (per millisecond).
Purpose: Completely eliminates server management tasks, operating system updates, idle server costs, and manual scaling logic.
Example: A taxi fare meter—you pay strictly for the exact seconds and distance you ride; cost is zero when standing still.
# Python AWS Lambda Handler Function Example import json def lambda_handler(event, context): # Process event payload data name = event.get('queryStringParameters', {}).get('name', 'Developer') return { 'statusCode': 200, 'headers': { 'Content-Type': 'application/json' }, 'body': json.dumps({'message': f'Hello {name}, from Serverless Lambda!'}) }
Task: Create a Lambda function in the AWS Console using Python or Node.js runtime and test it with a sample event payload.
8. Deploying Serverless APIs (Lambda + API Gateway)
Meaning: Connecting AWS API Gateway to AWS Lambda functions to build fully serverless REST APIs that scale automatically.
Definition: API Gateway acts as the public HTTP entry point that receives web requests, passes payloads to Lambda functions, and returns the response back to client applications.
Purpose: Builds enterprise-grade APIs that scale instantly from zero to millions of requests per second without managing backend web servers.
Example: An automated order kiosk receiving money at a front counter (API Gateway) and triggering an automated kitchen arm (Lambda) to fulfill the order.

PART 5: CLOUDFRONT CDN & CI/CD DEPLOYMENT PIPELINE
9. Amazon CloudFront (Content Delivery Network / CDN)
Meaning: A global Content Delivery Network (CDN) service that securely delivers web pages, videos, images, and APIs to users with low latency.
Definition: Caches static and dynamic web content across a worldwide network of over 400+ Edge Locations close to end users.
Purpose: Dramatically speeds up website loading times globally, lowers origin server load (S3/EC2), and provides free SSL/TLS HTTPS certificates.
Example: Placing small local distribution warehouses in every major city so online package orders arrive in 10 minutes instead of shipping from overseas every time.
# AWS CLI CloudFront Cache Invalidation (Clears old cached files) aws cloudfront create-invalidation \ --distribution-id E1A2B3C4D5E6F7 \ --paths "/*"
Task: Create a CloudFront Distribution pointing to an S3 bucket origin and observe the improved global HTTPS loading speed.
10. Development → Deployment Flow (CI/CD Pipeline)
Meaning: The complete automated workflow that builds, tests, and deploys software from a developer's computer to live production servers.
Definition: Continuous Integration (CI) automatically builds and tests code on every Git push; Continuous Deployment (CD) automatically deploys verified code to production (S3, EC2, Vercel, Netlify).
Purpose: Eliminates error-prone manual file transfers, speeds up release cycles, and ensures live software is always tested and operational.
Example: An automated newspaper assembly line—stories are typed, automatically proofread, printed, and delivered without manual human handing at each step.
# GitHub Actions CI/CD Pipeline Workflow (.github/workflows/deploy.yml) name: Deploy to Production S3 on: push: branches: [ "main" ] jobs: deploy: runs-on: ubuntu-latest steps: - name: Checkout Code uses: actions/checkout@v3 - name: Install & Build React App run: | npm install npm run build - name: Deploy to AWS S3 uses: jakejarvis/s3-sync-action@master env: AWS_S3_BUCKET: 'my-unique-app-bucket-2026' AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }} AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }} AWS_REGION: 'us-east-1' SOURCE_DIR: 'dist'
