🟢 Node.js Master Notes

Server-Side JavaScript Runtime Environment

PART 1: INTRODUCTION & ENVIRONMENT
1. Introduction to Node.js
Meaning: Node.js is an open-source JavaScript runtime that allows developers to run JavaScript code outside the web browser, especially on servers.
Definition: A cross-platform runtime environment built on top of Google Chrome's V8 JavaScript engine, created by Ryan Dahl in 2009. It uses a single-threaded event loop with non-blocking I/O operations.
Purpose: Enables developers to build fast, scalable network applications using JavaScript for both the front-end and back-end, allowing full-stack JavaScript development.
Example: Imagine a plant that only grew above ground (JavaScript in browsers) suddenly growing deep roots (Node.js) so the entire plant can live anywhere—on servers, IoT devices, or desktop apps.
// Save this as app.js and run with: node app.js console.log("Node.js is running JavaScript outside the browser!"); console.log("Node version:", process.version);
Task: Create a `hello.js` file that prints "Hello from Node!" and execute it in your terminal using `node hello.js`.
2. Node.js Environment Setup & Installation
Meaning: The complete process of downloading, installing, and configuring Node.js runtime on your computer so it can execute JavaScript server code.
Definition: Involves installing the official Node.js runtime (which bundles the V8 engine, standard library, and NPM) from nodejs.org, verifying installation via terminal commands, and setting up a code editor like VS Code.
Purpose: Prepares your development machine with all the required tools so JavaScript can be compiled and executed on your local machine without needing a browser.
Example: Setting up a fully-equipped home kitchen (environment) with a stove, utensils, and ingredients (Node + NPM + Editor) before you can start cooking (coding).

PART 2: NPM — PACKAGE MANAGER
3. NPM (Node Package Manager)
Meaning: NPM is the world's largest software registry and the official package manager automatically bundled with Node.js installations.
Definition: A command-line interface (CLI) tool used to install, update, uninstall, and manage external JavaScript packages (libraries) hosted at npmjs.com, documented inside a `package.json` manifest file.
Purpose: Simplifies dependency management by allowing developers to download pre-built libraries (like Express, React, Lodash) instead of writing every single function from scratch.
Example: Like a giant online supermarket where you can download pre-made tools and ingredients instead of making every single thing manually.
# Initialize a new Node.js project (creates package.json) npm init -y # Install Express library and save it as a dependency npm install express # Install nodemon as a dev dependency (for development only) npm install nodemon --save-dev # Install a specific version npm install express@4.18.0 # Remove a package npm uninstall express # Update all packages to latest allowed versions npm update
Task: Create a new project folder, run `npm init -y`, then install the `express` library and check that it appears inside the `node_modules` folder and `package.json` file.
4. package.json & package-lock.json Files
Meaning: Special metadata files automatically generated by NPM that describe your project, list its dependencies, and lock exact installed versions for reproducibility.
Definition: `package.json` stores project info (name, version, scripts, dependencies, author); `package-lock.json` locks the exact tree of installed dependency versions to prevent inconsistent installs across machines.
Purpose: Ensures that every developer working on the same project installs the exact same dependency versions, preventing the famous "but it works on my machine!" bug.
Example: A detailed shopping receipt listing every item, brand, and price so the exact same groceries can be rebought later without substitutions.
// package.json example { "name": "my-app", "version": "1.0.0", "scripts": { "start": "node app.js", "dev": "nodemon app.js" }, "dependencies": { "express": "^4.18.0" }, "devDependencies": { "nodemon": "^3.0.0" } } // Run custom script: npm run dev

PART 3: CALLBACKS CONCEPT
5. Callback Functions in Node.js
Meaning: A callback is a function passed as an argument into another function, which is executed later after the first function completes its asynchronous task.
Definition: A higher-order function pattern fundamental to Node.js that follows the "error-first" convention—the first parameter of the callback is always reserved for an error object, followed by the actual data result.
Purpose: Enables Node.js to execute long-running operations (like reading files, querying databases, or making HTTP requests) without blocking the main thread, keeping the server fast and responsive to new requests.
Example: Dropping off laundry at a dry cleaner and giving them your phone number so they can call you back when it's ready, instead of standing in the shop waiting.
// Error-first callback pattern const fs = require('fs'); fs.readFile('note.txt', 'utf8', function(err, data) { if (err) { console.error("Error reading file:", err); return; } console.log("File content:", data); }); console.log("This runs BEFORE file read completes!");

6. Callback Hell & Solutions
Meaning: Callback Hell (also called "Pyramid of Doom") refers to deeply nested callback functions that make code hard to read, debug, and maintain.
Definition: A code anti-pattern where multiple asynchronous operations are chained by nesting callbacks inside callbacks, creating a visual pyramid shape with excessive indentation levels.
Purpose: Understanding Callback Hell helps developers choose modern alternatives like Promises or Async/Await to write cleaner, more maintainable asynchronous code.
Example: Imagine giving a messenger an instruction letter, who gives it to another messenger with a nested letter, who hands it to a third messenger... soon no one knows what the original message was.
// ❌ Callback Hell Pattern (Pyramid of Doom) fs.readFile('a.txt', (err, a) => { fs.readFile('b.txt', (err, b) => { fs.readFile('c.txt', (err, c) => { fs.writeFile('out.txt', a + b + c, (err) => { console.log("Done!"); // Hard to read! }); }); }); }); // ✅ Solution: Use Promises or Async/Await

PART 4: EVENTS, EVENT LOOP & FILE UPLOADS
7. Node.js Events & EventEmitter
Meaning: Node.js uses an event-driven architecture where certain actions trigger named events that other parts of the code can listen for and react to.
Definition: Node.js provides the built-in `events` module with the `EventEmitter` class, which allows you to create, emit (fire), and listen for custom named events using methods like `.on()` and `.emit()`.
Purpose: Enables decoupled communication between different parts of an application, allowing code to react to things like file completion, HTTP requests, database connections, or custom app signals.
Example: A doorbell system—when someone presses the button (emit "doorbell"), everyone inside the house (listeners) hears it and can decide to react (open door, hide, etc.).
const EventEmitter = require('events'); // Create emitter instance const myEmitter = new EventEmitter(); // LISTEN for custom event myEmitter.on('user_signup', (username) => { console.log(`Welcome, ${username}! Sending email...`); }); // FIRE the event with data payload myEmitter.emit('user_signup', 'Alex'); myEmitter.emit('user_signup', 'Maya');
Task: Create an `EventEmitter` that listens for `order_placed` events and prints "Processing Order #" with an order ID passed as payload.
8. Event Loop in Node.js
Meaning: The Event Loop is the heart of Node.js that handles all asynchronous operations by continuously checking the event queue and executing pending callbacks.
Definition: A single-threaded, non-blocking mechanism that processes operations in phases (Timers → Pending Callbacks → Idle → Poll → Check → Close) using the libuv library behind the scenes.
Purpose: Allows Node.js to handle thousands of simultaneous connections efficiently on a single thread without needing multiple threads like traditional servers (Apache, Tomcat).
Example: A single waiter in a busy restaurant—instead of standing at one table waiting for guests to finish eating, the waiter continuously circulates, taking orders, delivering food, and clearing tables based on what's ready.
