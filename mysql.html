Relational Database Management System (RDBMS)

PART 1: DATABASE FOUNDATIONS & CREATION
1. Introduction to MySQL & Relational Databases
Meaning: MySQL is an open-source Relational Database Management System (RDBMS) that stores data in structured tables composed of rows and columns.
Definition: A server-based database system that uses Structured Query Language (SQL) to create, query, update, and manage relational data with ACID (Atomicity, Consistency, Isolation, Durability) guarantees.
Purpose: Organizes business data safely, enforces relationships between entities, and allows instant querying of millions of records with high security and reliability.
Example: A bank ledger keeping separate tables for "Customers", "Accounts", and "Transactions" linked together securely via unique ID numbers.
-- Connect to MySQL via terminal command mysql -u root -p -- View all existing databases on the server SHOW DATABASES;
Task: Install MySQL Server / XAMPP on your computer, open MySQL Workbench or command line, and list all databases using `SHOW DATABASES;`.
2. Creating & Selecting Databases
Meaning: A database is a master container that holds all related tables, views, stored procedures, and permissions for a specific application.
Definition: Created using the CREATE DATABASE statement and selected for query operations using the USE command.
Purpose: Separates data for different projects or environments (e.g. `ecommerce_dev`, `ecommerce_prod`) on the same server.
Example: Buying a new physical filing cabinet (`CREATE DATABASE`) and opening its door (`USE`) before filing documents inside.
-- Create a new database safely if it doesn't exist CREATE DATABASE IF NOT EXISTS school_db; -- Select database for active use USE school_db; -- Check currently selected database SELECT DATABASE();

3. Creating Tables & Data Types
Meaning: Tables are two-dimensional grids inside a database that store structured records in columns (fields) and rows (tuples).
Definition: Defined using the CREATE TABLE statement, specifying column names and SQL data types (`INT`, `VARCHAR`, `TEXT`, `DECIMAL`, `DATE`, `BOOLEAN`).
Purpose: Enforces structured schema rules so every record entered follows strict column formatting and type constraints.
Example: Drawing a printed registration table with strict columns for "Name", "Roll No", and "Birth Date".
CREATE TABLE students ( student_id INT, first_name VARCHAR(50), last_name VARCHAR(50), email VARCHAR(100), age INT, gpa DECIMAL(3, 2), enrollment_date DATE ); -- View table structure setup DESCRIBE students;

4. Primary Key & Auto Increment Constraints
Meaning: A Primary Key is a column (or set of columns) that uniquely identifies each individual row in a table. It cannot contain NULL or duplicate values.
Definition: Specified using PRIMARY KEY alongside AUTO_INCREMENT, which automatically generates a sequential unique ID (1, 2, 3...) for every new row added.
Purpose: Guarantees fast row retrieval, prevents duplicate entries, and establishes relationships with other tables.
Example: Passport numbers or Social Security Numbers—no two citizens can ever hold the exact same ID number.
CREATE TABLE users ( user_id INT AUTO_INCREMENT PRIMARY KEY, username VARCHAR(50) NOT NULL UNIQUE, email VARCHAR(100) NOT NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );
Task: Create a `products` table with `product_id` as an `AUTO_INCREMENT PRIMARY KEY` and test adding rows without specifying the ID manually.
5. Foreign Key Constraints
Meaning: A Foreign Key is a column in one table that references the Primary Key of another table, establishing a relationship between them.
Definition: Enforced using FOREIGN KEY (col) REFERENCES parent_table(primary_col), maintaining Referential Integrity across tables.
Purpose: Prevents orphan records (e.g. creating an order for a customer ID that doesn't exist in the customers table).
Example: A library book checkout ticket referencing a valid registered student ID card number.
CREATE TABLE orders ( order_id INT AUTO_INCREMENT PRIMARY KEY, order_date DATE, customer_id INT, amount DECIMAL(10, 2), -- Link customer_id to user_id in users table FOREIGN KEY (customer_id) REFERENCES users(user_id) ON DELETE CASCADE );

PART 2: CRUD OPERATIONS
6. CRUD - Create (INSERT INTO)
Meaning: Adding new records (rows) into an existing database table.
Definition: Executed using INSERT INTO table_name (cols) VALUES (vals), supporting single or multi-row batch inserts.
Purpose: Saves new entity data like user signups, new order creations, or blog post publishing.
Example: Filling out a new row on a physical guest sign-in registry page.
-- Single Row Insert INSERT INTO users (username, email) VALUES ('coder_alex', 'alex@mail.com'); -- Multi-Row Batch Insert INSERT INTO users (username, email) VALUES ('maya_dev', 'maya@mail.com'), ('john_doe', 'john@mail.com'), ('sarah_connor', 'sarah@mail.com');
Task: Insert 4 new employee records into your `employees` table using a single multi-row `INSERT INTO` statement.
7. CRUD - Read (SELECT Statements)
Meaning: Retrieving stored data records from database tables based on specified requirements.
Definition: Executed using SELECT columns FROM table_name. Using SELECT * fetches all available columns.
Purpose: Queries and projects data onto application user interfaces, dashboards, or reports.
Example: Opening a cabinet drawer and pulling out specific student file folders to read.
-- Retrieve ALL columns and ALL rows SELECT * FROM users; -- Retrieve SPECIFIC columns only (Better performance) SELECT username, email FROM users; -- Aliasing column names for cleaner output SELECT username AS Name, email AS 'Contact Email' FROM users;
Task: Write a query that fetches only the `name` and `salary` columns from your `employees` table with custom column aliases.
8. CRUD - Update (UPDATE ... SET)
Meaning: Modifying existing record values inside a database table.
Definition: Executed using UPDATE table_name SET col = val WHERE condition. CRITICAL: Always use a `WHERE` clause, or ALL rows will be overwritten!
Purpose: Updates changing data like password resets, profile edits, price changes, or status flags.
Example: Erasing an old home address on a record card and writing down a new one.
-- Update specific user email using ID UPDATE users SET email = 'alex_new@mail.com' WHERE user_id = 1; -- Update multiple columns simultaneously UPDATE users SET username = 'alex_pro', email = 'alex_pro@mail.com' WHERE user_id = 1;
Task: Write an `UPDATE` statement that increases the salary of an employee with `emp_id = 2` by 10%.
9. CRUD - Delete (DELETE FROM)
Meaning: Removing specific records permanently from a database table based on condition criteria.
Definition: Executed using DELETE FROM table_name WHERE condition. Without a `WHERE` clause, every single row in the table is deleted!
Purpose: Removes invalid, test, cancelled, or requested user-deleted records.
Example: Removing an expired membership record card from a filing drawer.
-- Delete specific record DELETE FROM users WHERE user_id = 3; -- Delete records matching condition DELETE FROM users WHERE created_at < '2020-01-01';

PART 3: FILTERING, SORTING & LIMITING
10. WHERE Clause & Operators
Meaning: Filters query results so that only rows meeting specific criteria are returned or modified.
Definition: Uses filtering comparison operators (=, !=, >, <, >=, <=), range operators (BETWEEN, IN), and wildcard pattern matching (LIKE '%val%').
Purpose: Restricts queries to precise target records instead of scanning entire huge tables.
Example: Asking a librarian to show you only books published after the year 2020.
-- Filter by numeric condition and logic SELECT * FROM students WHERE age >= 18 AND gpa >= 3.5; -- Filter using IN list and BETWEEN range SELECT * FROM students WHERE age BETWEEN 18 AND 22; SELECT * FROM students WHERE first_name IN ('Alex', 'Maya', 'John'); -- Wildcard search (LIKE % = any chars, _ = single char) SELECT * FROM students WHERE email LIKE '%@gmail.com';
Task: Write a query selecting all employees whose salary is between 50000 and 80000 and whose name starts with 'A'.
11. ORDER BY Clause (Sorting)
Meaning: Sorts the query result set in ascending or descending order based on one or more columns.
Definition: Appended to SELECT statements as ORDER BY col ASC (ascending - default) or ORDER BY col DESC (descending).
Purpose: Presents data logically, such as sorting products by price (low to high), users alphabetically, or posts by latest date.
Example: Arranging test score papers from highest score down to lowest score.
-- Sort by GPA descending (highest first) SELECT * FROM students ORDER BY gpa DESC; -- Multi-column sort: Sort by age ascending, then GPA descending SELECT * FROM students ORDER BY age ASC, gpa DESC;
Task: Select all employees and order them by `salary` descending, then by `name` ascending.
12. LIMIT & OFFSET Clauses (Pagination)
Meaning: Restricts the maximum number of rows returned by a query, with optional offset skipping.
Definition: LIMIT count restricts total rows; LIMIT count OFFSET skip skips specified rows before returning records.
Purpose: Essential for implementing database pagination (Page 1, Page 2...) and top-N ranking queries (e.g. Top 5 highest paid employees).
Example: Reading only 10 search result cards per page before clicking "Next Page".
-- Fetch Top 3 highest GPA students SELECT * FROM students ORDER BY gpa DESC LIMIT 3; -- Pagination: Skip 10 rows, fetch next 10 rows (Page 2) SELECT * FROM students ORDER BY student_id ASC LIMIT 10 OFFSET 10; -- Shorthand syntax: LIMIT 10, 10

PART 4: TABLE REMOVAL & CLEANUP
13. Removing Data: DELETE vs TRUNCATE vs DROP
Meaning: Three distinct ways to remove data or structure from a database, each operating at different system levels.
Definition: DELETE removes specific rows (DML - logged, rollback possible); TRUNCATE wipes ALL rows instantly and resets Auto Increment (DDL - fast); DROP destroys entire table schema and data permanently.
Purpose: Choose `DELETE` for conditional removal, `TRUNCATE` for resetting table data, and `DROP` for complete schema cleanup.
Example: DELETE = Erasing lines with an eraser; TRUNCATE = Wiping the entire whiteboard clean; DROP = Tearing the whiteboard off the wall and throwing it away.
-- 1. DELETE: Slow, row-by-row, conditional DELETE FROM logs WHERE log_date < '2023-01-01'; -- 2. TRUNCATE: Fast, wipes all data, resets AUTO_INCREMENT to 1 TRUNCATE TABLE test_logs; -- 3. DROP: Destroys complete table structure + data permanently DROP TABLE IF EXISTS old_backup_table;

PART 5: SQL JOINS (RELATIONAL QUERIES)
14. INNER JOIN
Meaning: Combines records from two tables only where there is a matching key relationship in both tables.
Definition: Executed as SELECT cols FROM TableA INNER JOIN TableB ON TableA.fk = TableB.pk. Unmatched rows in either table are excluded.
Purpose: Queries combined data across related tables (e.g. Orders WITH matched Customer details).
Example: Venn Diagram intersection area—returns only elements present in BOTH sets simultaneously.
SELECT orders.order_id, orders.amount, users.username, users.email FROM orders INNER JOIN users ON orders.customer_id = users.user_id;
Task: Write an `INNER JOIN` query connecting an `orders` table with a `products` table on `product_id`.
15. LEFT JOIN (LEFT OUTER JOIN)
Meaning: Returns ALL records from the Left table, along with matching records from the Right table. If no match exists, NULLs are returned for Right table columns.
Definition: Executed as SELECT cols FROM TableA LEFT JOIN TableB ON TableA.fk = TableB.pk. Guarantees no Left table row is omitted.
Purpose: Used when you want all primary entities regardless of whether they have linked child records (e.g. All Users, including users who placed 0 orders).
Example: Calling attendance for all registered students—students who haven't turned in homework still get listed with a blank (NULL) grade.
SELECT users.username, orders.order_id, orders.amount FROM users LEFT JOIN orders ON users.user_id = orders.customer_id; -- Users with 0 orders display order_id and amount as NULL
Task: Write a `LEFT JOIN` query finding all users who have placed 0 orders by checking `WHERE orders.order_id IS NULL`.
16. RIGHT JOIN (RIGHT OUTER JOIN)
Meaning: Returns ALL records from the Right table, along with matching records from the Left table. Unmatched Left values return NULL.
Definition: Executed as SELECT cols FROM TableA RIGHT JOIN TableB ON TableA.fk = TableB.pk. Mirror opposite of LEFT JOIN.
Purpose: Guarantees that every record in the target right-hand table is preserved in the query output.
Example: Listing all store products, even products that haven't been bought by any customer yet.
SELECT orders.order_id, users.username FROM orders RIGHT JOIN users ON orders.customer_id = users.user_id;

PART 6: AGGREGATE FUNCTIONS & GROUPING
17. Aggregate Functions: COUNT & SUM
Meaning: Built-in SQL functions that perform calculations across multiple row values and return a single summary value.
Definition: COUNT(col) counts non-NULL rows; SUM(col) calculates the total cumulative mathematical sum of numeric values.
Purpose: Calculates key performance indicators (KPIs) like total registered users, total revenue, or order volumes.
Example: Tallying up total cash register receipts at the end of a business day.
-- Count total number of users SELECT COUNT(*) AS total_users FROM users; -- Count distinct active cities SELECT COUNT(DISTINCT city) AS unique_cities FROM users; -- Calculate total sales revenue sum SELECT SUM(amount) AS total_revenue FROM orders;
Task: Calculate total number of employees and the total combined payroll sum from your `employees` table.
18. Aggregate Functions: AVG, MIN, MAX
Meaning: Summary functions that calculate mathematical average, minimum lowest value, and maximum highest value.
Definition: AVG(col) calculates numeric average; MIN(col) returns lowest value; MAX(col) returns highest value.
Purpose: Generates statistical metrics like average user GPA, lowest product price, or maximum order value.
Example: Finding the highest test score, lowest score, and class average score on an exam.
SELECT AVG(gpa) AS average_gpa, MIN(gpa) AS lowest_gpa, MAX(gpa) AS highest_gpa FROM students;
Task: Find the average, minimum, and maximum salary values from your `employees` table.
19. GROUP BY & HAVING Clauses
Meaning: GROUP BY groups rows sharing identical data into summary rows; HAVING filters grouped aggregate results (since `WHERE` cannot filter aggregates).
Definition: GROUP BY column collapses records per category; HAVING aggregate_condition filters categories after grouping.
Purpose: Calculates metrics per category (e.g. Total sales per country, Average salary per department).
Example: Grouping coins by denomination (1s, 5s, 10s) and then counting the total value in each pile.
-- Calculate total sales revenue PER customer SELECT customer_id, COUNT(order_id) AS total_orders, SUM(amount) AS total_spent FROM orders GROUP BY customer_id -- Filter groups: Only customers who spent over $500 total HAVING SUM(amount) > 500;
