▲ Next.js Master Notes

Full-Stack React Framework for Production

PART 1: NEXT.JS FOUNDATIONS
1. Introduction to Next.js
Meaning: Next.js is a powerful full-stack React framework created by Vercel for building production-ready web applications.
Definition: An open-source React framework that provides server-side rendering (SSR), static site generation (SSG), file-system routing, and built-in API support.
Purpose: Solves standard React Client-Side Rendering (CSR) limitations regarding SEO performance, slow initial page loads, and complex routing setup.
Example: Plain React is an engine requiring custom assembly; Next.js is a complete factory-assembled luxury car ready to drive.
// Next.js basic page component automatically routed at /about export default function AboutPage() { return <h1>Welcome to Next.js Production Web Application</h1>; }

2. Next.js Core Features
Meaning: Built-in capabilities that provide superior developer experience and web application performance automatically.
Definition: Key features include Hybrid Rendering (SSR/SSG/ISR), Automatic Code Splitting, Image/Font Optimization, and Zero-Config Routing.
Purpose: Maximizes Google Lighthouse SEO scores, speeds up page loads, and reduces manual webpack configuration.
Example: A smart smartphone camera automatically adjusting focus, lighting, and filters without manual tweaking.
import Image from 'next/image'; // Built-in Next.js automatic image optimization export default function Profile() { return <Image src="/user.jpg" alt="User" width={100} height={100} priority />; }

3. Component Lifecycle in Next.js
Meaning: How Next.js components execute across server execution environments and client browser hydrations.
Definition: Next.js components render on the server to generate HTML, send it to the browser, and then hydrate interactive JS on the client.
Purpose: Delivers instant visual content to users before full JavaScript execution completes in the browser.
Example: Receiving a fully printed physical newspaper immediately, then plugging in interactive audio buttons later.

PART 2: SERVER & CLIENT COMPONENTS
5. React Server Components (RSC)
Meaning: Components that render exclusively on the server, sending zero JavaScript bundle weight to the browser.
Definition: Default component mode in Next.js App Router that fetches data directly on the server without client bundle impact.
Purpose: Dramatically reduces JavaScript bundle sizes, secures database credentials, and improves overall application performance.
Example: A chef preparing food completely in the kitchen and serving the finished dish without bringing cooking equipment to your table.
// Default Server Component in App Router (Direct DB/API access) export default async function ProductList() { const res = await fetch('https://api.example.com/products'); const products = await res.json(); return ( <ul> {products.map((p) => <li key={p.id}>{p.name}</li>)} </ul> ); }
Task: Create a Server Component that fetches data directly inside the async component function without useState or useEffect.
6. Client Components ('use client')
Meaning: Interactive components that run on the client browser to handle state, hooks, and user click events.
Definition: Components explicitly marked with the 'use client' directive directive string placed at the very top of the file.
Purpose: Required whenever using browser APIs, React hooks (useState, useEffect), or event listeners (onClick, onChange).
Example: Bringing interactive games or touchscreen menus to a customer's table in a restaurant.
'use client'; // Explicit Client Component directive import { useState } from 'react'; export default function LikeButton() { const [likes, setLikes] = useState(0); return ( <button onClick={() => setLikes(likes + 1)}> Likes: {likes} </button> ); }

PART 3: DATA FETCHING STRATEGIES
7. Server-Side Rendering (SSR)
Meaning: Generating full page HTML dynamically on the server for every incoming user HTTP request.
Definition: Fetches fresh real-time data on every request using fetch(url, { cache: 'no-store' }) in App Router or getServerSideProps in Pages Router.
Purpose: Essential for dynamic content that changes constantly, such as stock tickers, live feeds, or user dashboards.
Example: Printing a personalized receipt live at the cashier register for every specific customer purchase.
// SSR in App Router (no caching = fetch on every request) export default async function LiveNews() { const res = await fetch('https://api.example.com/news', { cache: 'no-store' }); const news = await res.json(); return <div>Latest News: {news[0].title}</div>; }
Task: Fetch real-time data with `{ cache: 'no-store' }` and verify page HTML updates on every refresh.
8. Static Site Generation (SSG)
Meaning: Pre-rendering page HTML once at build time, serving static cached pages instantly to all visitors.
Definition: Default behavior in Next.js for pages without dynamic uncached data or using fetch(url, { cache: 'force-cache' }).
Purpose: Delivers maximum performance and lowest server overhead for content that changes infrequently (blogs, documentation).
Example: Printing 10,000 copies of a book in advance and distributing them immediately from a warehouse.
// SSG in App Router (default cached fetch) export default async function StaticDocs() { const res = await fetch('https://api.example.com/docs', { cache: 'force-cache' }); const docs = await res.json(); return <article>{docs.title}</article>; }
Task: Build a blog page using static fetching and inspect the build output using `npm run build`.
9. Incremental Static Regeneration (ISR)
Meaning: Updating specific static pages in the background without needing to rebuild the entire website.
Definition: Configured using the next: { revalidate: seconds } option in fetch requests to automatically regenerate cached HTML.
Purpose: Combines the ultra-fast performance of SSG with the freshness of real-time SSR data updates.
Example: Updating a printed store catalog automatically once every 60 seconds whenever prices change.
// ISR: Revalidate cached static page every 60 seconds export default async function Store() { const res = await fetch('https://api.example.com/products', { next: { revalidate: 60 } // Regenerate page every 60s }); const products = await res.json(); return <div>Products Updated Hourly</div>; }
Task: Configure a page with a 10-second revalidation time and observe cached background updates.
10. Data Fetching with React Query (TanStack Query)
Meaning: A powerful client-side state management library for fetching, caching, and updating server state in React/Next.js.
Definition: Uses hooks like useQuery and useMutation to handle loading states, caching, background refetching, and retries.
Purpose: Eliminates manual useEffect data fetching code and manages complex client-side API caching automatically.
Example: An automatic assistant periodically polling a server for new email notifications without reloading the page.
'use client'; import { useQuery } from '@tanstack/react-query'; export default function UserProfile() { const { data, isLoading, error } = useQuery({ queryKey: ['user'], queryFn: () => fetch('/api/user').then((res) => res.json()) }); if (isLoading) return <p>Loading...</p>; if (error) return <p>Error loading profile!</p>; return <h2>User: {data.name}</h2>; }

PART 4: ROUTING & FILE SYSTEM ARCHITECTURE
11. Pages Router (/pages Directory)
Meaning: The legacy file-system routing system where every file inside the `/pages` directory automatically maps to a URL route.
Definition: `pages/index.js` maps to `/`, `pages/about.js` maps to `/about`, and `pages/posts/[id].js` maps to dynamic paths `/posts/:id`.
Purpose: Simple routing structure used in older Next.js applications (v12 and earlier).
Example: Labeling physical paper folders inside a filing cabinet where folder names equal tab labels.
// File: pages/contact.js -> URL: http://localhost:3000/contact export default function Contact() { return <h1>Contact Us Page</h1>; }
Task: Create `pages/services.js` and verify it routes automatically to `/services`.
12. App Router (/app Directory & Layouts)
Meaning: The modern Next.js 13+ routing system built on React Server Components, nested layouts, and special file conventions.
Definition: Uses folders to define route segments containing special files: page.js, layout.js, loading.js, error.js.
Purpose: Enables nested shared UI layouts, parallel routes, and streaming UI state management.
Example: A master building template maintaining the header and footer while swapping individual room floor plans.
// File: app/dashboard/layout.js (Shared Layout) export default function DashboardLayout({ children }) { return ( <section> <nav>Dashboard Sidebar</nav> {children} {/* Renders app/dashboard/page.js */} </section> ); }
Task: Build an App Router layout file wrapping a persistent sidebar around sub-page views.
13. Dynamic Routes & Catch-All Segments
Meaning: Creating flexible URL routes that accept dynamic parameters or dynamic multi-segment paths.
Definition: Bracket syntax [id] creates single dynamic segments; [...slug] creates catch-all routes matching multiple sub-paths.
Purpose: Handles dynamic product pages, user profile URLs, or multi-level category documentation pages.
Example: A postal mailbox accepting letters addressed to any specific apartment number.
// File: app/blog/[slug]/page.js -> URL: /blog/hello-world export default function BlogPost({ params }) { return <h1>Reading Post: {params.slug}</h1>; } // File: app/docs/[...slug]/page.js -> URL: /docs/v1/setup/install // params.slug = ['v1', 'setup', 'install']
