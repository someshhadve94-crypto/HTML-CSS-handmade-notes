PART 1: OVERVIEW & ENVIRONMENT SETUP
1. Introduction to Django & Overview
Meaning: Django is a powerful, free, open-source Python web framework that encourages rapid development and clean, pragmatic design.
Definition: A full-stack, batteries-included server-side web framework following the MVT (Model-View-Template) architectural pattern, created by Adrian Holovaty and Simon Willison in 2005.
Purpose: Allows developers to build secure, scalable, and maintainable web applications quickly by including pre-built features like an Admin Interface, ORM, Authentication, and CSRF protection out of the box.
Example: Renting a fully furnished apartment where the plumbing, electricity, furniture, and security system are already set up, so you can move in immediately without building the house from scratch.

2. Django Environment Setup
Meaning: Preparing your development machine by creating an isolated Virtual Environment (`virtualenv`) and installing the Django package via PIP.
Definition: Virtual environments prevent package version conflicts by isolating project dependencies from the global system Python installation.
Purpose: Guarantees that every Django project runs with its own specific dependencies without breaking other Python projects on your computer.
Example: Giving each room in a house its own dedicated temperature controller so adjusting one room doesn't disrupt the temperature in other rooms.
# 1. Create a virtual environment named 'env' python -m venv env # 2. Activate Virtual Environment # On Windows: env\Scripts\activate # On Mac/Linux: source env/bin/activate # 3. Install Django inside the active environment pip install django

PART 2: PROJECTS, APPS & VIEWS
3. Creating a Django Project
Meaning: A Django Project is the top-level container for an entire website, containing database configurations, settings, URLs, and modular applications.
Definition: Initialized using django-admin startproject project_name, which creates core control files: `settings.py`, `urls.py`, `wsgi.py`, `asgi.py`, and `manage.py`.
Purpose: Establishes global site configuration, database connections, middleware layers, and master routing rules.
Example: Building a shopping mall structure (Project) that will house individual separate stores (Apps) inside it.
# Initialize project named 'mywebsite' django-admin startproject mywebsite cd mywebsite # Run local development server python manage.py runserver # Access server at: http://127.0.0.1:8000/

4. Creating a Django App
Meaning: A Django App is a web application submodule designed to perform a specific, self-contained business function (e.g. blog, user auth, store catalog).
Definition: Created using python manage.py startapp app_name. Must be registered inside the `INSTALLED_APPS` array in `settings.py`.
Purpose: Promotes modularity and reusability—a single App (like a blog or comment app) can be copied and reused across multiple Django projects.
Example: A clothing store inside a shopping mall—it operates independently within the larger mall structure.
# Create application module named 'blog' python manage.py startapp blog # Register app in mywebsite/settings.py: INSTALLED_APPS = [ 'django.contrib.admin', 'django.contrib.auth', ... 'blog', # Registered application ]

5. Creating Views in Django
Meaning: A View is a Python function or class that receives an HTTP request, processes logic, and returns an HTTP response (HTML, JSON, Redirect, 404).
Definition: Function-Based Views (FBVs) accept `request` as their first parameter and return an `HttpResponse` or `render()` object; connected via `urls.py`.
Purpose: Handles application request-response workflow and connects database models to presentation templates.
Example: A customer service representative who listens to customer requests, looks up information, and responds back with an answer.

PART 3: MVT ARCHITECTURE
6. MVT Architecture Overview
Meaning: MVT (Model-View-Template) is Django's software architectural design pattern used to decouple data, logic, and presentation.
Definition: A variation of MVC where Django itself acts as the Controller handling URL mapping and routing automatically.
Purpose: Separates database structure, business execution logic, and visual layout design into distinct layers for modular development.
Example: Restaurant workflow: Pantry holds raw food (Model), Kitchen cooks meals (View), Dining room serves formatted dishes (Template).
/* MVT Workflow Architecture: 1. USER sends HTTP Request -> URL Dispatcher (urls.py) 2. URL routes request to matching VIEW (views.py) 3. VIEW queries MODEL (models.py) for database records 4. VIEW passes data to TEMPLATE (.html) to build page 5. VIEW returns HTTP Response back to User Browser */

7. Model Layer in MVT
Meaning: The data layer responsible for defining database structure, field attributes, constraints, and business data logic using Python classes.
Definition: A Python class inheriting from `models.Model` where class attributes represent database table columns.
Purpose: Maps Python objects directly to underlying SQL tables via Django's Object-Relational Mapper (ORM), avoiding raw SQL writing.
Example: A blueprint drawing defining the structure of a customer record (name, phone, address).
# File: blog/models.py from django.db import models class Post(models.Model): title = models.CharField(max_length=200) content = models.TextField() created_at = models.DateTimeField(auto_now_add=True)
Task: Create a `Product` model class inside `models.py` with `name`, `price`, and `created_at` fields.
8. View Layer in MVT
Meaning: The processing logic layer that receives HTTP requests, fetches data from Models, executes operations, and selects Templates for output.
Definition: Functions or classes inside `views.py` containing business logic that coordinate data between Models and Templates.
Purpose: Executes backend operations, handles form validation, authentication, and prepares data for visualization.
Example: A chef gathering ingredients from the pantry (Model) and preparing them into a meal to place on a plate (Template).
# File: blog/views.py from django.shortcuts import render from .models import Post def post_list(request): posts = Post.objects.all() # Fetch data from Model return render(request, 'blog/post_list.html', {'posts': posts})

9. Template Layer in MVT
Meaning: The visual presentation layer composed of HTML files embedded with Django Template Language (DTL) tags to generate dynamic web pages.
Definition: HTML files located inside a `templates/` directory containing dynamic tags (`{% %}`), variables (`{{ }}`), and filters.
Purpose: Renders dynamic database information inside HTML layout structures for display in client web browsers.
Example: A blank paper document with pre-formatted placeholders where dynamic names and dates are printed.
<!-- File: templates/blog/post_list.html --> <h1>Blog Posts</h1> <ul> {% for post in posts %} <li><strong>{{ post.title }}</strong> - {{ post.created_at }}</li> {% empty %} <li>No posts found.</li> {% endfor %} </ul>

PART 4: TEMPLATE SYSTEM & INHERITANCE
10. Django Template Language (DTL) Syntax
Meaning: Django's built-in template syntax that allows inserting variable values, logic loops, conditional statements, and formatting filters inside HTML.
Definition: Uses Variables {{ variable }}, Tags {% tag %}, Filters {{ value|filter }}, and Comments {# comment #}.
Purpose: Evaluates dynamic Python view data cleanly inside static HTML files without executing raw Python code.
Example: Filling in personal fields on an automated form printing template.
<!-- DTL Syntax Examples --> <h1>Welcome, {{ username|title }}!</h1> {% if user.is_authenticated %} <p>Status: Logged In</p> {% else %} <a href="/login">Please Log In</a> {% endif %}

11. Master Templates & Template Inheritance
Meaning: A mechanism allowing a master base HTML template to define a common layout structure (header, navbar, footer) inherited by child templates.
Definition: Base templates define placeholder regions using {% block name %}{% endblock %}; child templates inherit layouts using {% extends 'base.html' %}.
Purpose: Eliminates HTML code duplication across pages, maintaining a consistent navigation header and footer site-wide.
Example: A company letterhead paper—the top logo and bottom contact address stay identical while the message content body changes.
<!-- 1. Master Template: templates/base.html --> <!DOCTYPE html> <html> <head><title>My Site</title></head> <body> <nav>Shared Navbar</nav> <div class="content"> {% block content %}{% endblock %} </div> <footer>Shared Footer</footer> </body> </html> <!-- 2. Child Template: templates/home.html --> {% extends 'base.html' %} {% block content %} <h1>Home Page Body Content</h1> {% endblock %}

PART 5: MODELS & ADMIN INTERFACE
12. Django Models & Model Fields
Meaning: Defining database table schema blueprints in Python using Django's built-in field types.
Definition: Model class attributes mapping to SQL column types: `CharField`, `TextField`, `IntegerField`, `DecimalField`, `BooleanField`, `DateTimeField`, `ForeignKey`.
Purpose: Establishes table structure, column constraints (`max_length`, `null`, `blank`, `default`), and model relationships cleanly.
Example: Setting up a digital registration form with specific rules for text length, numbers, and dates.
from django.db import models class Category(models.Model): name = models.CharField(max_length=100) class Product(models.Model): name = models.CharField(max_length=200) description = models.TextField(blank=True) price = models.DecimalField(max_digits=10, decimal_places=2) is_available = models.BooleanField(default=True) category = models.ForeignKey(Category, on_delete=models.CASCADE) def __str__(self): return self.name

13. Django Migrations
Meaning: Django's system for translating changes made inside `models.py` into executable SQL database schema statements.
Definition: python manage.py makemigrations creates SQL blueprint migration files; python manage.py migrate executes them against the database.
Purpose: Keeps your database tables synchronized with Python model code as your application structure evolves.
Example: Updating an architect's blueprint first (makemigrations) and then carrying out the physical construction work (migrate).
# 1. Generate migration files based on model changes python manage.py makemigrations # 2. Apply migrations to database (Creates SQL tables) python manage.py migrate

PART 6: DATA OPERATIONS (DJANGO ORM)
16. Inserting Data (Create)
Meaning: Creating and saving new model record instances into the database using Django ORM.
Definition: Done by instantiating a model object and calling .save(), or using Model.objects.create() directly.
Purpose: Inserts records from form submissions or API payloads programmatically into database tables.
Example: Filling out a new record form in Python and saving it to the database file.
# Method 1: Instantiation + save() prod = Product(name="Laptop", price=999.99) prod.save() # Method 2: Direct objects.create() (Automatic save) prod = Product.objects.create(name="Phone", price=599.99)

17. Querying & Filtering Data (Read)
Meaning: Retrieving database records using Django ORM QuerySet API methods.
Definition: Methods: Model.objects.all(), .filter(), .exclude(), .get(), along with field lookups (`__icontains`, `__gte`, `__exact`).
Purpose: Fetches specific data subsets cleanly without writing manual SQL SELECT queries.
Example: Searching a database for all products priced under $100 containing the word "wireless".
# Fetch ALL records all_prods = Product.objects.all() # Fetch SINGLE matching record (raises error if 0 or >1 found) single_prod = Product.objects.get(id=1) # Filter with Field Lookups cheap_prods = Product.objects.filter(price__lte=100.00) search_prods = Product.objects.filter(name__icontains="phone")

18. Updating Data (Update)
Meaning: Modifying field values of existing model instances stored in the database.
Definition: Fetch instance -> update attribute -> call .save(); or update multiple rows at once using QuerySet.update().
Purpose: Updates records in response to user edits, status changes, or batch processing.
Example: Modifying a user's account status or applying a discount to a group of products.
# Method 1: Single Record Update prod = Product.objects.get(id=1) prod.price = 899.99 prod.save() # Method 2: Batch Update multiple records Product.objects.filter(is_available=False).update(price=0.00)

19. Deleting Data (Delete)
Meaning: Removing model instances permanently from database tables using ORM methods.
Definition: Executed by calling .delete() on a single model instance or an entire filtered QuerySet.
Purpose: Removes expired or user-deleted records from database tables.
Example: Deleting an item from a shopping list database.
# Delete Single Record prod = Product.objects.get(id=1) prod.delete() # Batch Delete multiple records matching filter Product.objects.filter(is_available=False).delete()

PART 7: FORMS, FILE UPLOADS, SESSIONS & CACHING
21. Django Forms Processing
Meaning: Managing HTML form rendering, input validation, error handling, and security using Django Form classes.
Definition: Created using `forms.Form` or `forms.ModelForm`. Validated inside views using form.is_valid() and form.cleaned_data. Automatically includes CSRF token security via `{% csrf_token %}`.
Purpose: Automates HTML form rendering, secures forms against cross-site request forgery attacks, and validates user inputs.
Example: An automated form checker validating that an email contains "@" before allowing form submission.
# File: blog/forms.py from django import forms from .models import Product class ProductForm(forms.ModelForm): class Meta: model = Product fields = ['name', 'price', 'description'] # File: blog/views.py def create_product(request): form = ProductForm(request.POST or None) if form.is_valid(): form.save() # Automatic model insert return redirect('product_list') return render(request, 'product_form.html', {'form': form})

22. File & Image Uploading in Django
Meaning: Handling user file and image uploads by binding media fields to model instances and storing assets on disk.
Definition: Uses `FileField` or `ImageField` in models; requires setting `MEDIA_URL` and `MEDIA_ROOT` in `settings.py`, handling `request.FILES` in views, and adding `enctype="multipart/form-data"` to HTML forms.

23. Cookies Management in Django
Meaning: Small text key-value pairs stored directly inside the user's browser to persist state across HTTP requests.
Definition: Set on response objects via response.set_cookie('key', 'val') and read from request objects via request.COOKIES.get('key').
Purpose: Remembers user preferences like dark mode settings, visitor tracking IDs, or language selections.
Example: A website remembering your preferred site theme selection when you return to the page later.
def set_theme(request): response = render(request, 'theme.html') response.set_cookie('theme', 'dark', max_age=86400) # 1 day return response def get_theme(request): user_theme = request.COOKIES.get('theme', 'light') # Default light return HttpResponse(f"Current Theme: {user_theme}")

24. Sessions Management in Django
Meaning: Server-side state storage linked to a unique session cookie ID stored in the user's browser.
Definition: Accessed inside views via dictionary-like interface request.session['key'] = value. Data is stored securely in the server database by default.
Purpose: Stores sensitive user data across page navigations, such as user login IDs, user permissions, and shopping cart contents.
Example: A locker room key given to a gym member—the key (session ID) opens a specific locker containing their belongings (session data).
def add_to_cart(request, product_id): cart = request.session.get('cart', []) cart.append(product_id) request.session['cart'] = cart # Save to session return redirect('cart_view') def cart_view(request): cart = request.session.get('cart', []) return render(request, 'cart.html', {'cart_items': cart})

25. Caching System in Django
Meaning: Storing the result of expensive calculations or database queries in high-speed memory to serve future requests faster.
Definition: Configured in `settings.py` (Memcached, Redis, Database, In-Memory). Applied via view decorator @cache_page(60 * 15) or low-level API `cache.set() / cache.get()`.
Purpose: Reduces database server load, speeds up page load times, and improves site scalability.
Example: Keeping printed copies of popular reports on your desk so you don't have to re-query the database every time someone requests them.
from django.views.decorators.cache import cache_page # Cache view response for 15 minutes (900 seconds) @cache_page(60 * 15) def heavy_news_feed(request): # Heavy database queries execute only once per 15 minutes! articles = Article.objects.all() return render(request, 'feed.html', {'articles': articles})
